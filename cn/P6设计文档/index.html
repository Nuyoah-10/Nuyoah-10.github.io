设计思路

流程步骤

  • 将存储器进行外置
  • 分析新添加指令集特征，同类指令一起添加
  • 进行controller,alu等模块修改
  • 分析新加指令的转发和暂停逻辑
  • 检验完成支持28条指令的流水线CPU

需求概括

  • 32位五级流水线处理器
  • 支持指令集为：add, sub, and, or, slt, sltu, lui, addi, andi, ori, lb, lh, lw, sb, sh, sw, mult, multu, div, divu, mfhi, mflo, mthi, mtlo, beq, bne, jal, jr (共28条)

阻塞与转发模块

与 P5 中的转发部分相同，
新添加了乘除模块的阻塞。

转发条件 :

  • 读寄存器等于写寄存器编号且不为0
  • 写寄存器使能有效
  • t_use和t_new都存在且t_use >= t_new
阻塞部分

寄存器写使能部分：E、M、W级寄存器 en=1,clear=0
只在D级阻塞，若需阻塞，则
PC_en = D_en = 0; E_clear = 1;
PC和D级寄存器保持不变，E级寄存器clear相当于插入空泡。

阻塞条件 :

  • 读寄存器等于写寄存器编号且不为0
  • 写寄存器使能有效
  • t_use和t_new都存在且t_use < t_new

测试方案

思考题

  • 为什么需要有单独的乘除法部件而不是整合进 ALU？为何需要有独立的 HI、LO 寄存器？

因为乘除法的计算周期比其余指令长很多，如果整合进ALU会大大增加关键路径时间，阻塞时间也会增加，拖慢CPU整体的运行效率。
需要独立的HI和LO是因为乘除法的结果可能不会立即读出，需要保存下来且保证不会被其他新的乘除以外的指令覆盖掉。新增这两个寄存器可以更好地达到保存乘除结果的功能，其余指令均不会使用到这两个寄存器。

  • 真实的流水线 CPU 是如何使用实现乘除法的？请查阅相关资料进行简单说明。

真实的CPU会将乘除法拆解为多个阶段，如乘法拆解为“部分积生成→部分积累加→移位”等3-5个阶段，除法分“比较→减法→移位→商生成”等4-6个阶段），每个阶段对应流水线的一个节拍。
例如MIPS R4000处理器的乘法器为8级流水线，除法器为10级流水线，运算过程中部件内部自流水线化，不占用ALU资源。

  • 请结合自己的实现分析，你是如何处理 Busy 信号带来的周期阻塞的？

首先在Controller模块中定义start信号，遇到乘除指令时定义start=1，在MDU模块中定义cnt信号，在start=1时将cnt初始化为需要模拟的阻塞周期数，每个周期cnt递减1直到cnt=0，busy信号在cnt>0时一直保持为1，cnt=0时恢复至0。
在HCU模块中，如果此时D级为乘除指令，而E级的start或者busy信号为1，则将D级的指令进行阻塞。

  • 请问采用字节使能信号的方式处理写指令有什么好处？（提示：从清晰性、统一性等角度考虑）

清晰性：支持非对齐存储访问，字节使能信号可精准定位需写入的字节，无需硬件额外处理对齐问题，四位字节分别对应8位，简单明了。
统一性：不同字节的写指令可通过统一的字节使能信号表示写入，无需为每种指令设计单独的写控制逻辑。

  • 请思考，我们在按字节读和按字节写时，实际从 DM 获得的数据和向 DM 写入的数据是否是一字节？在什么情况下我们按字节读和按字节写的效率会高于按字读和按字写呢？

按字节读：DM按地址取出对应32位数据，通过DE模块选中目标字节，再经符号扩展为32位后送入下一级。实际从DM获得的是1字。
按字节写：DM仅将数据中目标字节写入对应存储单元，其余3个字节保持不变。实际向DM写入的是有限个字节，但传输的是1字。
当读写数据均为单字节时前者效率高，不需要进行拼接等其余操作。

  • 为了对抗复杂性你采取了哪些抽象和规范手段？这些手段在译码和处理数据冲突的时候有什么样的特点与帮助？

对于lw/lh/lb,sw/sh/sb等类似的指令，进行统一添加，减少复杂性。
译码采用控制信号驱动型，每次添加指令时批量修改控制信号。
处理冲突时基本与P5相同，只需新增乘除模块的阻塞机制，减小工作量。

  • 在本实验中你遇到了哪些不同指令类型组合产生的冲突？你又是如何解决的？相应的测试样例是什么样的？

主要涉及的是乘除模块的冲突，但是由于数据保证每次乘除后就会执行mfhi和mflo，且HI和LO寄存器在乘除法以外的指令都不会涉及，所以无脑阻塞即可。其余冒险沿用之前的转发通路就可以解决。

随机生成的测试样例，可以短时间大量产生数据，但是其指令覆盖度不足，转发和阻塞正确性难以得到检验，还容易由于跳转指令陷入死循环。
先手动把死循环的数据修改掉，使得程序覆盖率加强；另外手动添加未涉及的指令，全面测试单独的指令正确性；最后在一些指令周围前后加上涉及同个寄存器读写的指令，检查阻塞转发值是否正确。
