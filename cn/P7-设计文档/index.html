设计思路

流程步骤

  • 完成CP0协处理器
  • 在流水线中识别各种异常情况，并随流水线传输至CP0中
  • 添加timer0,timer1（教程已给出）
  • 添加bridge,完成CPU和tb等的信号传输
  • 将mips设为顶层线路，实例化CPU,timer0,timer1,bridge

需求概括

  • 32位支持中断异常的五级流水线处理器
  • 支持指令集为：add, sub, and, or, slt, sltu, lui, addi, andi, ori, lb, lh, lw, sb, sh, sw, mult, multu, div, divu, mfhi, mflo, mthi, mtlo, beq, bne, jal, jr，mfc0, mtc0, eret, syscall（新增四条）

000000 5 5 5 00000 6
具体功能

（以下所有rs,rt,rd均代表GPR[rs],GPR[rt],GPR[rd]）

指令名 funct 描述

sub 100010 rd ← rs - rt
and 100100 rd ← rs AND rt
or 100101 rd ← rs OR rt
slt 101010 rd ← (rs < rt) 有符号
sltu 101011 rd ← (rs < rt) 无符号
mult 011000 (HI,LO) ← rs × rt 有符号
multu 011001 (HI,LO) ← rs × rt 无符号
div 011010 (HI,LO) ← rs / rt 有符号
divu 011011 (HI,LO) ← rs / rt 无符号
mfhi 010000 rd ← HI
mflo 010010 rd ← LO
mthi 010001 HI ← rs
mtlo 010011 LO ← rs
jr 001000 PC ← rs

思考题

  • 请查阅相关资料，说明鼠标和键盘的输入信号是如何被 CPU 知晓的？

鼠标和键盘的输入信号均通过中断驱动机制告知CPU。再经驱动程序、系统内核等环节完成数据处理与传递，最终让CPU知晓具体输入内容。二者流程类似，仅硬件编码、中断标识等细节有差异。

  • 请思考为什么我们的 CPU 处理中断异常必须是已经指定好的地址？如果你的CPU支持用户自定义入口地址，即处理中断异常的程序由用户提供，其还能提供我们所希望的功能吗？如果可以，请说明这样可能会出现什么问题？否则举例说明。（假设用户提供的中断处理程序合法）

CPU 处理中断异常时依赖固定入口地址，本质是为了保证中断响应的确定性、安全性和执行效率。支持用户自定义中断入口地址，可以实现基本的中断处理功能，但是可能打破内核与用户态的隔离边界，侵占其它内存，有一定风险。

  • 为何与外设通信需要 Bridge？

使用Bridge核心是解决CPU和外设间协议、速率、地址等不兼容问题，同时降低CPU负担、优化系统架构，转移了工作量，有利于CPU的功能维护和扩展。

  • 请阅读官方提供的定时器源代码，阐述两种中断模式的异同，并分别针对每一种模式绘制状态移图。

在计数为0后行为不同

  • 倘若中断信号流入的时候，在检测宏观 PC 的一级如果是一条空泡（你的 CPU 该级所有信息均为空）指令，此时会发生什么问题？在此例基础上请思考：在 P7 中，清空流水线产生的空泡指令应该保留原指令的哪些信息？

保存的返回信息会消失。空泡指令应该保存是否是延迟槽指令，以及PC地址，否则无法返回。

  • 为什么 jalr 指令为什么不能写成 jalr $31, $31？

jalr的操作是PC <- GPR[rs], GPR[rd] <- PC + 4，若后两个寄存器相同，则先跳转再写入和先写入再跳转结果会冲突。
